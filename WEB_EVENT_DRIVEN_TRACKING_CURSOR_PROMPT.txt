## Task: Event-driven desktop tracking ingest + server-side duration projection (desktop v1.3.0+)

The Electron desktop agent (v1.3+) uses a **hybrid** model:

1. **Transition events** (`APP_CHANGE`, `IDLE_*`, `ACTIVITY_START`/`STOP`, `HEARTBEAT`) — timestamps only; server projects per-app time.
2. **`INPUT_ACTIVITY` every 15s** — still includes mouse move %, keyboard %, click counts, `mouseMoveCount`, `keyPressCount`, `activityScore`, `validEngagedSeconds`, etc. **Keep existing activity breakdown UI for this.**
3. **`ACTIVITY_INTERVAL` every 15 min** — unchanged rollup blocks.

The web app must:

1. **Accept** the new `eventKind` values on batch ingest.
2. **Keep** `INPUT_ACTIVITY` aggregation for mouse/keyboard/click breakdown (do not remove).
3. **Compute per-app durations** server-side from `APP_CHANGE` (not `APP_FOCUS.activeSeconds`).
4. **Keep** legacy event handling for older desktop builds.
5. **Apply** `eventUuid` idempotency (see `WEB_TRACKING_IDEMPOTENCY_PROMPT.txt` if not done yet).

**Fix server ingest, persistence, projection, and UI read paths.** Do not change the Electron desktop app for this task.

## Why this changed

| Old desktop (pre-v1.3) | New desktop (v1.3+) |
|------------------------|---------------------|
| Poll input every 2s, emit `INPUT_ACTIVITY` every 15s | **Still** — full mouse/keyboard/click metrics in `INPUT_ACTIVITY` |
| `APP_FOCUS` with `activeSeconds` credited locally | `APP_CHANGE` with timestamp only (no `activeSeconds`) |
| Web sums `APP_FOCUS.activeSeconds` for apps used | Web diffs `APP_CHANGE` timestamps for app time |
| Activity % from `INPUT_ACTIVITY` | **Unchanged** — still use `INPUT_ACTIVITY` / `ACTIVITY_INTERVAL` |

Desktop batch sync runs every **~60s**. Events may arrive slightly out of order within a batch; sort by `occurredAt` before projection.

### New `eventKind` values to accept

```

ACTIVITY_STOP
APP_CHANGE
IDLE_START
IDLE_END
HEARTBEAT
SCREENSHOT_CAPTURED
```

### Legacy kinds (still accept — do not remove)

```
INPUT_ACTIVITY
APP_FOCUS
HEARTBEAT          (old shape may include activeSeconds)
ACTIVITY_INTERVAL
```

### Validation rules

1. Every event has stable **`eventUuid`** (UUID v4). Idempotent re-ingest → `{ ok: true, duplicate: true }`.
2. **`occurredAt`** (ISO 8601 UTC) is the authoritative timestamp for projection. Do not use server receive time for duration math.
3. **Do not require** `activeSeconds`, `trackerElapsedMs`, `activityScore`, or mouse/keyboard percents on new kinds.
4. **Do require** session linkage fields when present on desktop payload:
   - `workDateKey` (YYYY-MM-DD in user/client TZ)
   - `sessionId` / `workSessionId` (when server session exists)
   - `projectId` (nullable for catalog/non-chargeable tasks)
   - `sessionSegmentStartedAt` (ISO — desktop segment start)
   - `clientTimeZone` (IANA, e.g. `America/New_York`)
5. Extend Zod/OpenAPI/Prisma enums to include new kinds without rejecting the batch.

System idle transitions (desktop threshold: **5 minutes** via `GetLastInputInfo`).

```json

  "metadata": { "triggerType": "idle_transition" }
```

```json

  "metadata": { "triggerType": "idle_transition" }
}
```

### `HEARTBEAT`

Every **~45s** while session active. Liveness + optional foreground snapshot. **Not** a duration sample.


## Server-side projection (required)

Persist raw events, then project into read models used by reports / session detail / timeline UI.

### Sort order

```ts
events.sort((a, b) => Date.parse(a.occurredAt) - Date.parse(b.occurredAt));
```

### Session tracked time

For v1.3 sessions prefer:

```
trackedMs = ACTIVITY_STOP.occurredAt - ACTIVITY_START.occurredAt
```

Fallback if `ACTIVITY_*` missing: existing session stop API `startedAt` / `stoppedAt`.

Subtract explicit idle segments if your product defines “active time” vs “clock time”:

```
activeMs = trackedMs - sum(idle_segment_ms)
idle_segment_ms = IDLE_END.occurredAt - IDLE_START.occurredAt  (paired in order)
```

### Per-app time (replaces summing `APP_FOCUS.activeSeconds`)

Walk `APP_CHANGE` events in order within a session segment:

```ts
for each APP_CHANGE at time T:
  duration until next APP_CHANGE or ACTIVITY_STOP or session end
  credit to (processName, applicationDisplayName, windowTitle at T)
```

Pseudocode:

```ts
function projectAppSegments(events: TrackingEvent[]): AppSegment[] {
  const changes = events.filter(e => e.eventKind === 'APP_CHANGE');
  const stopAt = findStopTime(events); // ACTIVITY_STOP or session stop
  const segments: AppSegment[] = [];

  for (let i = 0; i < changes.length; i++) {
    const start = Date.parse(changes[i].occurredAt);
    const end = i + 1 < changes.length
      ? Date.parse(changes[i + 1].occurredAt)
      : stopAt;
    if (end > start) {
      segments.push({
        processName: changes[i].processName,
        application: changes[i].applicationDisplayName ?? changes[i].appName,
        windowTitle: changes[i].windowTitle,
        startedAt: new Date(start).toISOString(),
        endedAt: new Date(end).toISOString(),
        durationMs: end - start
      });
    }
  }
  return segments;
}
```

### Idle segments

Pair `IDLE_START` → `IDLE_END` in order. Unclosed `IDLE_START` at session stop → close at `ACTIVITY_STOP.occurredAt`.

### Heartbeat usage

- **Liveness**: if no `HEARTBEAT` for > 3× 45s (~135s) during an open session, flag gap / offline (do not invent events).
- **Do not** treat heartbeat as 45s of active time.

### Legacy sessions

If session has `INPUT_ACTIVITY` / `APP_FOCUS` / `ACTIVITY_INTERVAL` events, keep existing aggregation for that session. Detect v1.3 by presence of `ACTIVITY_START` or `metadata.agentVersion === "event-driven-v1"`.

```ts
function isEventDrivenSession(events: TrackingEvent[]): boolean {
  return events.some(e =>
    e.eventKind === 'ACTIVITY_START' ||
    e.metadata?.agentVersion === 'event-driven-v1'
  );
}
```

## Web UI changes

### Session detail / timeline

| UI element | Old source | New source (v1.3) |
|------------|------------|-------------------|
| Total tracked | Sum `INPUT_ACTIVITY` windows or session API | `ACTIVITY_STOP - ACTIVITY_START` (or session API) |
| Apps used | Sum `APP_FOCUS.activeSeconds` | Projected `APP_CHANGE` segments |
| Idle blocks | `idleSeconds` on samples | `IDLE_START` / `IDLE_END` pairs |
| Activity % / mouse % | Per-sample desktop metrics | **Not available** from v1.3 agent unless you add server-side inference later |
| Screenshots | Screenshot ingest | Same ingest + optional `SCREENSHOT_CAPTURED` marker on timeline |

### Live session timer on web

Web can compute display time from `session.startedAt` → `now` client-side (same as desktop UI). No need for per-second desktop events.

### Desktop ↔ web session mirror

Desktop polls remote session every **30s**. Start/stop API behavior unchanged. `ACTIVITY_START` / `ACTIVITY_STOP` are **additional** analytics events, not a replacement for session start/stop endpoints.
