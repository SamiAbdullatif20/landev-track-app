## Task: Fix `POST /api/tracking/events/batch` — stop 400s, drain desktop retry queue

Desktop tracker **v1.1.1** shows **“Could not upload tracking data (N pending)”** when batch ingest returns **400** with a generic body like `{ "error": "Something went wrong" }`. Thousands of `APP_FOCUS` / `INPUT_ACTIVITY` events already ingest; failures cluster around **session stop/start same day**, **`ACTIVITY_INTERVAL`**, and **new v1.1 fields**.

**Fix batch ingest + persistence only in this task.** Report UI (clicks, meeting time, timeline colors) can follow using the other `WEB_*` prompts — but ingest must accept and store the fields now so nothing is dropped.

**Do NOT change the Electron desktop app.**

## Required batch behavior

### 1. Per-event success (do not fail entire batch on one bad row)

Return **200** with per-event results when possible:

```json
{
  "ok": true,
  "ingested": 18,
  "failed": 2,
  "results": [
    { "eventUuid": "…", "ok": true },
    { "eventUuid": "…", "ok": false, "error": "duplicate_interval" }
  ]
}
```

If you keep all-or-nothing transactions today, fix validation so rows that desktop sends are valid. Desktop v1.1.1 now retries **one event at a time** after a batch failure, but the server must still accept valid rows.

### 2. Idempotent on `eventUuid`

Desktop retries the same `eventUuid` after offline / 400. Re-posting the same event must **return success**, not 400/409.

```ts
// Pseudocode
const existing = await db.trackingEvent.findUnique({ where: { eventUuid } });
if (existing) return { ok: true, duplicate: true };
```

### 3. Persist unknown fields (do not strip)

Store full event JSON in `metadata` or JSON column. Desktop sends many keys top-level **and** duplicated in `metadata`. **Rejecting unknown keys** causes `Something went wrong`.

Use `.passthrough()` / `.strict(false)` in Zod, or an explicit allowlist that includes every field in section 5 below.

### 4. `workSessionId` resolution

If `workSessionId` / `sessionId` is missing:

- Resolve from authenticated `userId` + `workDateKey` + active `WorkSession`, **or**
- Create/link session server-side

**Never silently drop** events with valid `workDateKey` + `eventUuid`.

### 5. Fix Redis / DB 500s

Past production issue: Redis `expire` wrong arity → 500 on batch. Grep batch handler for `expire(` and fix. Return structured JSON, not generic 500 HTML.

## `ACTIVITY_INTERVAL` — critical for sync failures

Emitted at each 15-minute wall-clock boundary in the employee timezone.

### Shape (top-level + metadata)

```json
{
  "eventUuid": "d9a378e3-38ab-43d8-bec4-6fcb29f2f629",
  "eventKind": "ACTIVITY_INTERVAL",
  "type": "ACTIVITY_INTERVAL",
  "occurredAt": "2026-06-22T15:45:00.000Z",
  "workDateKey": "2026-06-22",
  "workSessionId": "724",
  "sessionId": "724",
  "sessionSegmentStartedAt": "2026-06-22T15:44:26.282Z",
  "clientTimeZone": "Europe/Istanbul",
  "projectId": "1604",
  "intervalMinutes": 15,
  "intervalStartAt": "2026-06-22T15:44:26.282Z",
  "intervalEndAt": "2026-06-22T15:45:00.000Z",
  "trackedSeconds": 30,
  "activeSeconds": 28.5,
  "idleSeconds": 1.5,
  "validEngagedSeconds": 27,
  "validKeyboardSeconds": 10,
  "validMouseSeconds": 18,
  "validClickSeconds": 5,
  "keyboardActivityPercent": 33.33,
  "mouseActivityPercent": 60,
  "clickActivityPercent": 16.67,
  "engagementActivityPercent": 90,
  "activityScore": 90,
  "estimatedEfficiencyPercent": 95,
  "activityLevel": "high",
  "timelineColor": "green",
  "metadata": { "sampleCount": 2, "antiCheatFlags": [], "source": "tracking-activity-interval" }
}
```

### Segment-split intervals (v1.1.1)

When employee **stops and starts inside the same 15-minute block**, desktop clamps:

```
intervalStartAt = max(wallClockBlockStart, sessionSegmentStartedAt)
```

Example: wall block 15:30–15:45, new segment starts 15:44:26 → `intervalStartAt` = **15:44:26**, not 15:30.

**Unique key must include segment**, not only wall clock:

```ts
// ✅ Correct — two segments same wall block, same workSessionId
unique: [userId, workSessionId, sessionSegmentStartedAt, intervalStartAt, intervalEndAt]

// ❌ Wrong — second segment 400s as duplicate
unique: [workSessionId, intervalStartAt, intervalEndAt]
```

### Validation rules

- `trackedSeconds` may be **much less than 15 minutes** (partial block / new segment) — **do not reject**
- `intervalEndAt` = `intervalStartAt` + 15 min (wall-clock end of block) even when `intervalStartAt` is clamped
- `activityScore` on v1.1+ intervals equals `round(engagementActivityPercent)` — trust desktop value for timeline

## Activity score version gate (for report UI — store now, display later)

```ts
function isUnionEngagementEvent(event: TrackingEvent): boolean {
  return (
    event.validEngagedSeconds != null ||
    event.engagementActivityPercent != null ||
    event.metadata?.validEngagedSeconds != null
  );
}

function timelineActivityScore(event: TrackingEvent): number {
  if (isUnionEngagementEvent(event)) {
    return Math.round(
      event.engagementActivityPercent ??
      event.metadata?.engagementActivityPercent ??
      event.activityScore ??
      0
    );
  }
  // Legacy sessions only
  const kb = event.keyboardActivityPercent ?? 0;
  const mouse = event.mouseActivityPercent ?? 0;
  return Math.round((kb + mouse) / 2);
}
```

See `WEB_ACTIVITY_TIMELINE_SCORING_PROMPT.txt` for full timeline UI rules.
